# Sprout: project rules

- The spec is docs/PLAN.md. If code and plan disagree, stop and ask.
- TypeScript strict. No `any`, no `@ts-ignore`, no non-null `!` on data from storage.
- All randomness goes through `src/engine/rng.ts`. Never call Math.random().
- All dates go through `src/lib/clock.ts` so tests can freeze time.
- All persistence goes through the `Repo` interface. No direct localStorage or IndexedDB calls in components.
- All speech goes through `src/audio/speech.ts`.
- Every storage write is awaited inside try/catch and surfaces a visible error state on failure.
- One React component per file, one default export, file name matches component name.
- Every route is registered in `src/app/routes.tsx` and nowhere else.
- The repo is public. No secrets, no email addresses and no real names in it, in code, tests, fixtures or commit messages. Secrets live in Cloudflare Worker settings and in `.dev.vars`, which git ignores.
- Every `/api` route except the sign-in routes checks the session before doing anything else.
- The Worker reaches D1, R2 and email only through the interfaces in `worker/store.ts` and `worker/mailer.ts`, so tests run with in-memory versions.
- The Worker never reads or changes the backup file's contents. Merging happens on the device.
- No GitHub Actions. The Cloudflare build runs `npm run verify` before every deploy.
- No `window.open`. External links use `<a target="_blank" rel="noopener noreferrer">` and exist only in parent mode.
- Kid screens: tap targets at least 64px, no text-only instructions below grade 1, no timers unless the parent turned the timer on (one exception the owner chose: fast facts is always a race), nothing that moves away before the child answers, no negative sounds.
- Layout: mobile first, flex column, scroll inside panels, never horizontal page scroll. Use `dvh`, not `vh`.
- Every new skill needs: a generator file, a catalogue row, and a pass from the generator test suite.
- Before finishing any phase run the audit in section 13 of the plan.
- The score is called "Skill Score" everywhere in the app. Never show the word SmartScore.
- The main device is an iPad running the app from the Home Screen. Follow the iPad rules in section 3.
- Never change what an existing seed produces without bumping that skill's version and its golden file.
- Day boundaries use `localDay()` from `src/lib/clock.ts`. Never work out a day from a UTC string.
- A `listen` question never shows its target and its options never speak. A `read` question never speaks the words the child must read.
- Saved references are skill ids, never positions in a list.
- Kid navigation replaces history. It never pushes a new entry.
- Dev routes exist only when `import.meta.env.DEV` is true.
- Spoken text is built from `Say` parts. Letters, numbers, times and money are typed parts, never digits or symbols inside a string.
- New fields on a stored record always have a zod default, so old records still load.
- Colours are named once: UI colours in `src/styles/tokens.css`, colours a child is asked about in `src/content/data/colors.ts`, picture colours in `src/visuals/palette.ts`. No colour is written anywhere else.
- Component style files hold no pixel or rem sizes. Sizes, borders and icon sizes are tokens in `tokens.css`.
- Screens use the shared components in `src/components/` (`BigButton`, `LinkButton`, `TextField`, `Notice`, `FormCard`, `FormLinks`, `SkillTile`, `TileGrid`, `Tabs`, `Column`, `FullScreenCard`, `QuestionStage`, `HoldButton`). A screen never writes its own `<button>`, `<label>` or alert box. `tests/repo/style.test.ts` enforces these three rules.

## Working rules for every phase

- Do exactly one phase per session. Stop when its gate (plan section 12) passes and report the gate output.
- Run `npm run verify` before saying a phase is done, and paste the result.
- If the gate fails, fix the cause. Never weaken, skip or delete a test.
- Do not add a dependency that is not listed in plan section 3. Ask first.
- No placeholders, no TODO stubs, no mock data in shipped screens.
- Commit at the end of the phase with message "Phase N: <name>".
- Ask the owner in multiple-choice form before deciding anything the plan leaves open. Do not assume.
- A push to `main` deploys the family's live app. Push only when the owner asks.

## The server and the device (decided by the owner on Nov 16, 2026: this replaces the plan's backup-file sync)

- The owner first chose online-only storage, then settled on: the server holds the main copy, each device keeps its own copy, and the app opens and practises with no internet.
- Server: the D1 table `records` (family, store, key, value). `worker/data.ts` has `GET /api/data` (paged) and `POST /api/data` (one transaction). The Worker never looks inside a record. Every listed parent shares the family `family`; on the local test server each account is its own family.
- `worker/index.ts` may export only functions beside its default. Any other named value stops the Worker from starting. `tests/worker/config.test.ts` guards this.
- Device: `src/storage/online.ts` `trackedBackend(device)` wraps the IndexedDB backend. Every write to a family store also writes a note in the `outbox` store (IndexedDB version 2), in the same transaction. `device`, `clips` and `outbox` never leave the device.
- `src/storage/sync.ts` `makeSyncer`: `run()` fetches every server row, merges it with `importAll` (so the tested merge rules apply), then sends the outbox. `send()` only sends. A row merged in from the server that equals the server's copy is not noted, so it is never sent back. A device's first run notes everything it holds (`movedOnline`).
- `src/storage/index.ts`: a change is sent 300 ms after it is made. `syncFamily()` runs at launch, on the picker and home, when the app returns to the front (at most every 10 seconds), on the `online` event, and every 30 seconds while offline. `watchSync` tells the app how each run went. A run the server refuses (401) changes nothing: the sign-in check alone decides whether the device is signed in.
- `store.link` is `waiting` only on a device that has never fetched (the picker would look empty), otherwise `ready` or `offline`. Offline shows a notice, never a blocking screen. `store.dataVersion` goes up when records arrive, and the picker and the grown-up screens read again.
- `repo.saveAnswer` saves one answer and everything it changes in one write, so it goes up in one request.
- The removed-videos list is in the family record now. `savePin` keeps the rest of the family record.
- Gone: the R2 backup sync, `FirstSync`, `BackupStatus`, the `dirty` flag. `/api/backup` and the R2 file are still there, unused, as a safety copy. The Data screen shows `OnlineStatus`.
- Unit tests run with no server. A test that wants one calls `setDataApiForTests(fakeDataApi(), device)`; see `tests/app/online.test.tsx` and `tests/storage/online.test.ts`.
- Browser-test helpers that write straight into IndexedDB must also write the outbox note, or the record never reaches a second device (`finishCheckIn` in `e2e/support/kid.ts` does).
- Before deploying a schema change: `npx wrangler d1 execute sprout --remote --file worker/schema.sql` (safe to run more than once).
